## Data Extraction Flow

### 1. Value Streams Extraction

```
ChromaDB Documents
    │
    ├─→ Check metadata['value_stream']
    ├─→ Check metadata['vs_code']
    ├─→ Check metadata['category']
    ├─→ Pattern match filename (O2C_*.pdf)
    │
    ↓
Unique Value Streams
    │
    ├─→ O2C (Order to Cash)
    ├─→ P2P (Procure to Pay)
    ├─→ R2R (Record to Report)
    │
    ↓
API Response: /api/value-streams
{
  "value_streams": [
    {"code": "O2C", "name": "Order to Cash"},
    {"code": "P2P", "name": "Procure to Pay"}
  ]
}
```

### 2. Health Scores Calculation

```
For each Value Stream:
    │
    ├─→ Query documents by vs_code
    │
    ├─→ Count total documents (coverage)
    ├─→ Scan content for issues:
    │       - "problem", "error", "bug"
    │       - "pain point", "bottleneck"
    │       - "challenge", "risk"
    │
    ├─→ Calculate scores:
    │       base_score = min(100, doc_count/10 * 100)
    │       issue_penalty = issues * 2
    │       process_health = base_score - issue_penalty
    │       system_health = base_score - issue_penalty * 1.2
    │
    ├─→ Determine RAG status:
    │       ≥80 = Green
    │       ≥65 = Yellow
    │       ≥50 = Amber
    │       <50 = Red
    │
    ↓
API Response: /api/health-scores
[{
  "vs_code": "O2C",
  "process_health": 85.5,
  "system_health": 78.3,
  "readiness_score": 81.9,
  "rag_status": "Green",
  "finding_count": 25,
  "painpoint_count": 8
}]
```

### 3. KPI Extraction

```
For each Document:
    │
    ├─→ Pattern match content:
    │       - "KPI: Name - Value"
    │       - "Rate: 85%"
    │       - "Target: X days"
    │
    ├─→ Extract metrics:
    │       - kpi_name
    │       - current_value
    │       - numeric_value
    │       - unit (%, days, USD)
    │
    ├─→ Generate targets (20% improvement)
    │
    ├─→ Determine direction (higher/lower)
    │
    ↓
API Response: /api/kpis?vs_code=O2C
{
  "kpis": [{
    "vs_code": "O2C",
    "kpi_name": "Order Fulfillment Rate",
    "current_value": "82.5%",
    "target_value": "95.0%",
    "target_direction": "higher"
  }]
}
```

## Component Responsibilities

### ChromaDB Vector Store
- **Stores**: Document chunks + embeddings + metadata
- **Provides**: Semantic search, metadata filtering, collection stats
- **Location**: `./chroma_db/` directory
- **Size**: Grows with document count

### ChromaDataExtractor (`chroma_data_extractor.py`)
- **Extracts**: Value streams from metadata
- **Calculates**: Health scores from content analysis
- **Parses**: KPIs using pattern matching
- **Caches**: Results for performance

### API Server (`api_server.py`)
- **Initializes**: Pipeline and data extractor on startup
- **Serves**: REST endpoints for frontend
- **Handles**: Analysis jobs, file uploads, queries
- **Provides**: Real-time data from ChromaDB

### React Frontend (`UI/`)
- **Dashboard**: Displays health scores and value streams
- **AI Chat**: RAG-powered Q&A interface
- **Knowledge Base**: Document management
- **Reports**: Visualizations and analytics
- **Insights**: Analysis job monitoring

## Startup Sequence

```
1. python api_server.py
   │
   ├─→ Initialize ERPHealthCheckPipeline
   │
   ├─→ Load VectorStore from ./chroma_db/
   │   │
   │   ├─→ Success: ChromaDB loaded with N documents
   │   └─→ Fail: "Vector store not found. Run analysis first."
   │
   ├─→ Initialize ChromaDataExtractor
   │   │
   │   ├─→ Extract value streams (cached)
   │   ├─→ Pre-calculate health scores (cached)
   │   └─→ Prepare for KPI queries
   │
   └─→ Start FastAPI server on port 8000
       │
       └─→ Log: "ChromaDB data extractor initialized with X documents"

2. cd UI && npm start
   │
   ├─→ Start React dev server on port 3000
   │
   ├─→ Fetch /api/value-streams
   ├─→ Fetch /api/health-scores
   ├─→ Fetch /api/v1/statistics
   │
   └─→ Render Dashboard with real-time data
```

## Performance Optimization

### Caching Strategy
```python
# ChromaDataExtractor uses in-memory cache
self._cache = {}

# First call - slow (queries ChromaDB)
value_streams = extractor.get_value_streams()  # ~100ms

# Subsequent calls - fast (from cache)
value_streams = extractor.get_value_streams()  # <1ms
```

### Query Optimization
```python
# Efficient: Single query with filter
data = collection.get(
    where={"value_stream": "O2C"},
    include=['metadatas', 'documents']
)

# Inefficient: Multiple small queries
for doc_id in all_ids:
    doc = collection.get(ids=[doc_id])
```

## Error Handling

```
API Request → Data Extractor → ChromaDB
                  │
                  ├─→ Success: Return data
                  │
                  ├─→ No Data Found: 404 "No value streams found"
                  │
                  ├─→ Not Initialized: 404 "Run analysis first"
                  │
                  └─→ Internal Error: 500 "Error message"
```

## Data Freshness

**Real-time Updates**:
1. Add new documents to `./data/input/`
2. Run `python data_ingestion.py`
3. Restart API server: `python api_server.py`
4. Frontend automatically fetches new data

**No manual file generation needed!**

## Scalability

|-----------|---------------|------------|------------------|
